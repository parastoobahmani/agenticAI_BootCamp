# پروژهٔ سادهٔ Agentic Support با LangChain

این پروژه یک دستیار پشتیبانی برای مسائل **Streamlit** است؛ رابط خود پروژه خط فرمان است. مدل در حالت LIVE با `create_agent` ابزار بعدی را انتخاب می‌کند. شش ابزار، حافظهٔ SQLite و توقف ماندگار برای تصمیم انسان دارد. هیچ تغییری روی GitHub واقعی ایجاد نمی‌کند.

## سند دقیقاً چه می‌خواهد؟

۱. از گزارش‌های واقعی، نظرات، مستندات و تغییرات نسخه‌ها شواهد قابل ارجاع پیدا کنیم؛ ابهام، نسخهٔ منبع و فرضیه را مشخص کنیم.

۲. بر اساس اطلاعات موجود و بررسی‌های انجام‌شده، سؤال تشخیصی مناسب یا مسیر ارجاع پیشنهاد کنیم و پاسخ کاربر و خلاصهٔ نگه‌دارنده بسازیم.

۳. پرونده را در چند نوبت حفظ کنیم. عامل ابزارها را انتخاب کند، نتیجه و خطا را ببیند و برای انتشار نظر یا تغییر وضعیت و برچسب منتظر انسان بماند.

۴. تأیید به همان پیشنهاد و همان نسخهٔ پرونده محدود باشد؛ ویرایش، رد، restart، تکرار درخواست و خرابی نباید باعث تغییر اشتباه یا تکراری شود.

۵. حداقل ۳۰ پرونده با تقسیم ۱۵/۱۵، ده سناریوی چندنوبتی، baseline، معیارهای کیفیت و هزینه و سقف ۵ دلار داشته باشیم. بخش «مسئلهٔ ۲، بخش ۳» سهم ارائهٔ شماست.

## نصب روی Windows / Anaconda

در پوشهٔ همین نسخه، یک محیط جدا بسازید؛ فایل‌ها را روی محیط قدیمیِ خراب اجرا نکنید.

```text
conda create -n agentic_student python=3.12 -y
conda activate agentic_student
python -m pip install -r requirements-lock.txt
```

`requirements.txt` وابستگی‌های اصلی را نشان می‌دهد. `requirements-lock.txt` نسخه‌های دقیق محیط آزمایش‌شده را دارد. این پیاده‌سازی NumPy، SciPy و scikit-learn را import نمی‌کند.

## ارائه بدون API و بدون هزینه

```text
python main.py init-demo
python main.py --demo run demo
python main.py --demo review demo
```

در فرمان سوم، پیشنهاد کامل نمایش داده می‌شود. `approve`، `edit` یا `reject` وارد کنید. در حالت `edit`، JSON جدید بدهید؛ مثال `{"comment":"متن جدید"}`. ویرایش فقط پیشنهاد تازه می‌سازد؛ برای تأیید آن دوباره `review` اجرا کنید.

حالت DEMO از **مدل جعلی و تصمیم‌های از پیش نوشته‌شده** استفاده می‌کند؛ گراف LangChain، ابزارها، توقف، حافظه و تراکنش پایگاه داده واقعی‌اند. DEMO معیار هوشمندی مدل نیست و هزینهٔ API ندارد.

## استفادهٔ واقعی از API خودتان

```text
copy .env.example .env
```

فایل `.env` را با URL ارائه‌دهنده، نام مدل دارای قابلیت tool calling، کلید و قیمت واقعی ورودی/خروجی بر حسب دلار برای یک میلیون توکن تکمیل کنید. URL معمولاً تا `/v1` است، نه تا `/chat/completions`. پروژه آن را خودکار می‌خواند.

برای اینکه اجرای LIVE با نمونهٔ قبلی مخلوط نشود، یک پروندهٔ تازه بسازید:

```text
python main.py create mycase --title "Streamlit loading behind nginx" --body "The deployed page keeps loading."
python main.py run mycase
python main.py review mycase
python main.py cost
```

حذف `--demo` یعنی LIVE. نبودن کلید یا خطای سرویس اجرای LIVE را متوقف می‌کند؛ برنامه پنهانی به پاسخ جعلی تغییر حالت نمی‌دهد. `MODE: LIVE` فقط حالت را اعلام می‌کند. `[API] attempt` تلاش، و `[API] response_received` دریافت پاسخ را نشان می‌دهد. `cost` تعداد تلاش‌ها، پاسخ‌های موفق و مصرف گزارش‌شده را نمایش می‌دهد. صورتحساب قطعی در داشبورد ارائه‌دهنده است.

فرمان `review` تصمیم انسانی را به گراف می‌دهد؛ متن گزارش یا پیشنهاد مدل نمی‌تواند آن را جایگزین کند. تأیید و اجرای ابزار محلی مستقل از موفقیت پاسخ نهایی مدل‌اند؛ اگر API بعد از ثبت نظر قطع شود، ثبت قبلی را با `show` و `audit` بررسی کنید.

## ادامهٔ گفتگو، دیدن وضعیت و بازیابی

نمونهٔ زیر برای PowerShell نوشته شده است:

```powershell
python main.py update demo --message "Version is 1.50.0" --facts '{"streamlit_version":"1.50.0"}'
python main.py --demo run demo
python main.py --demo review demo
python main.py show demo
python main.py audit demo
```

اگر یک بررسی انجام شده، آن را همراه نتیجه ثبت کنید:

```powershell
python main.py update demo --message "WebSocket returns 403" --check '{"name":"websocket","result":"403"}'
```

اصلاح اطلاعات، شمارهٔ نوبت و نسخه را افزایش می‌دهد و پیشنهادهای قبلی را نامعتبر می‌کند. `recover ID` اجرای متوقف‌شدهٔ گراف را از checkpoint ادامه می‌دهد؛ برای تأییدِ در انتظار از `review ID` استفاده کنید. در حالت demo پیشوند `--demo` را حفظ کنید.

```text
python main.py --demo recover demo
python main.py reset --yes
```

`reset` فقط پرونده‌ها و checkpoint محلی را پاک می‌کند؛ دفتر هزینه حفظ می‌شود. اگر `CASE_EXISTS` دیدید، شناسهٔ جدید انتخاب کنید یا فقط برای دادهٔ آزمایشی reset بزنید.

## شش ابزار

| ابزار | ورودی اصلی | خروجی | اثر قابل مشاهده نیازمند تأیید |
|---|---|---|---|
| `read_case` | ندارد؛ پرونده در Session ثابت است | facts، checks، history، summary | خیر |
| `search_docs` | query | قطعه‌های منبع، شناسه، URL، نسخه و امتیاز | خیر |
| `draft_reply` | متن، نوع تصمیم، دلیل، ابهام‌ها و منابع | پیشنهاد پاسخ و خلاصهٔ شش‌بخشی | هنوز منتشر نمی‌کند |
| `draft_status` | open / closed | پیشنهاد وضعیت | هنوز اعمال نمی‌کند |
| `draft_labels` | فهرست برچسب‌ها | پیشنهاد برچسب | هنوز اعمال نمی‌کند |
| `apply_change` | proposal_id | interrupt، یا رسید، یا خطا | **بله؛ برای هر سه نوع تغییر** |

مدل ابزار `approve` ندارد. برای بسته‌شدن پرونده، علاوه بر تأیید اپراتور، کاربر باید واقعاً حل مشکل را اعلام کرده باشد و این fact به صورت boolean ثبت شود؛ `"resolved": true`. بسته‌بودن یک گزارش GitHub، اثبات حل مشکل فعلی نیست.

## فایل‌ها را به چه ترتیب بخوانم؟

۱. `main.py`: فرمان‌ها و مسیر ورود اطلاعات انسان.
۲. `src/agent.py`: ساخت عامل، شش ابزار و توقف انسانی.
۳. `src/store.py`: حافظه، پیشنهاد، تأیید، تراکنش و رسید.
۴. `src/retrieval.py`: TF-IDF و رتبه‌بندی محلی.
۵. `src/budget.py`: اتصال API و محدودیت هزینه.
۶. `src/demo_model.py`: مدل جعلیِ مخصوص ارائه و تست.

ارزیابی و سناریوها جدا از کد اصلی‌اند: `evaluate.py`، `scenarios.py` و `tests/`. پوشهٔ `tools/` فقط برای جمع‌آوری یا بازسازی داده و ساخت مثال است؛ برای اجرای روزمره لازم نیست.

نقشهٔ دقیق ارتباط کد و بندهای سند در `docs/Code_Map_FA.md` آمده است. توضیح فارسی در `docs/Code_Explanation_FA.pdf` و متن مستقل بخش شما در `docs/Practical_Scenarios_FA.pdf` قرار دارد. `docs/Input_Output_FA.md` ورودی و خروجی اجرای همین کد را نشان می‌دهد.

## تست و ارزیابی

```text
python -m unittest discover -s tests -v
python scenarios.py
python evaluate.py
```

آزمون API از HTTP جعلی استفاده می‌کند و هزینه ندارد. ده سناریو با گراف واقعی LangChain و مدل جعلی اجرا می‌شوند. گزارش‌ها در `reports/` ذخیره می‌شوند. هر سناریو ورودی اولیهٔ یک گزارش واقعی دارد، ولی پاسخ‌های بعدی و تصمیم انسان طراحی‌شده‌اند و چنین برچسب خورده‌اند.

برای بررسی کیفیت مدل واقعی ابتدا دو پرونده را اجرا کنید و پاسخ‌ها را دستی بخوانید:

```text
python evaluate.py --live --split dev --limit 2
python evaluate.py --live --split dev --limit 15
python evaluate.py --live --split test --limit 15
```

این فرمان baseline تک‌پاسخی و عامل ابزارمحور را روی ورودی مشترک اجرا می‌کند؛ نظر منتشر نمی‌کند و منتظر انسان باقی می‌ماند. هزینهٔ هر دو از یک دفتر مشترک کم می‌شود. خطا یا تمام‌شدن بودجه، ارزیابی را با حفظ نتایج جزئی متوقف می‌کند. خروجی هر اجرا مسیر تازه دارد و `human_review.csv` باید توسط اعضای گروه تکمیل شود.

گزارش فعلی فقط ارزیابی محلی بازیابی است: Recall@4 روی زیرمجموعهٔ دارای برچسب مرتبط در dev برابر ۱۸٫۷۵٪ برای baseline و ۲۵٪ برای روش نهایی است؛ در test هر دو ۲۰٪ هستند. این نتیجه، بهبود کیفیت پاسخ LLM را ثابت نمی‌کند. تقسیم موجود قبلاً دیده شده و اجرای فعلی «بازارزیابی» است، نه آزمون کور جدید. اگر مدرس آزمون واقعاً ندیده می‌خواهد، باید خانواده‌های تازه انتخاب و split جدید پیش از تنظیم روش ثابت شود.

## داده و محدودیت‌های صادقانه

snapshot شامل ۲۴۰ گزارش، ۵۶ نظر و ۱۴ سند است. پیکرهٔ جست‌وجو پس از حذف خانواده‌های ارزیابی و اشاره‌های مستقیم، ۳۲۷ بخش منبع دارد. metadata و نسخه‌ها در `data/snapshot/manifest.json` هستند؛ بازسازی پیکره با `python tools/rebuild_knowledge.py` انجام می‌شود. `collect_snapshot.py` فقط هنگام نیاز به snapshot تازه اجرا شود؛ دادهٔ اینترنت با زمان تغییر می‌کند و نباید آن را جایگزین خاموش آزمایش ثابت کرد.

Embedding در این نسخه بردار تنک واژگانی TF-IDF است، نه embedding معنایی عصبی. هم‌معنی‌ها و پرسش کاملاً فارسی ممکن است بازیابی ضعیفی داشته باشند؛ نام API و کلیدواژهٔ انگلیسی در query مفید است. گروه‌بندی اولیهٔ خانواده‌ها heuristic بوده و بررسی انسانیِ نشت معنایی هنوز لازم است. امتیاز شباهت، احتمال درست‌بودن تشخیص نیست.

هیچ ارزیابی پرداخت‌شده با کلید واقعی شما در بسته انجام نشده است. اتصال LangChain/OpenAI با انتقال HTTP جعلی آزمایش شده است. مدل ارائه‌دهندهٔ شما باید tool calling و پارامترهای این کلاینت را پشتیبانی کند.

سقف ۵ دلار بر اساس نرخ‌های واردشده و دفتر مشترک اعمال می‌شود. همهٔ اعضا باید از یک `TEAM_LEDGER` استفاده کنند؛ هزینهٔ اجراهای بیرون این برنامه خودکار قابل مشاهده نیست. رزرو مصرف تقریبی است و در خطای مبهم آزاد نمی‌شود. این دفتر جای صورتحساب سرویس را نمی‌گیرد. کلید، فایل `.env` و پوشهٔ `runtime` را تحویل ندهید.
